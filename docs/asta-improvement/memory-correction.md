# Correct, restore and forget memories without losing evidence

- **Correction supersedes.** `correct_memory` (agent, HTTP and MCP) stores the right fact with `supersedes:` set to the old one. The old fact is preserved in `.history` and marked `superseded_by`, `superseded_at` and `why`; its body is never rewritten. It then leaves recall and `MEMORY.md`. A fact is corrected once. Episodes and paths outside `facts/` are refused.
- **Restore drill.** `memory.restore()` compares memory against the newest nightly snapshot, or a named one. It reports what is intact, missing, changed, corrupt and purged, and changes nothing. With `apply=True` it restores missing and changed files byte for byte from `.history`, checking each copy against its recorded hash. A copy that does not match its hash is reported and never written. A file being overwritten is preserved first.
- **Explicit deletion only.** `forget_memory` acts only when Arun's own words in the turn ask to forget or delete. It removes the fact from `facts/`, the search index and `MEMORY.md`, and a copy stays restorable in `.history`. `purge` needs him to say "permanently" or similar. It removes every recorded version from `.history` and lists those digests in `purged.json`, so a restore reports them as purged instead of bringing them back.
- **Fixed in passing:** recall snippets read FTS column 4 (`date`) instead of 3 (`body`), so every recalled memory reached the prompt as its date, and re-ranking compared against that date. Recall now carries the memory's content.

Limits: nothing decides on its own that a fact is wrong. A correction is made when he or a brain calls `correct_memory`. Episodes are not correctable, only restorable. Restore works from snapshots taken by nightly consolidation, so changes made since the last snapshot are covered only by the pre-change copies kept in `.history`.
